## Decisions & assumptions

- **CENTRAL_ADMIN sees every alert.** The geo-target fix exposed a worse problem: an admin *publishes*
  a "Central Delhi" alert and it was invisible in their own list. I added central command to the
  effective-regions set (AD-39) rather than shipping that. Flagging it because it is a policy choice,
  not a technical necessity — if command should only see its own alerts, it is a one-line change.
- **A department maps to every NCR region.** `DEPARTMENTS` (AD-34) are city-wide responder units with
  no per-region roster in the data model, so a finer mapping would be invented. If per-region teams
  are ever modelled, `DEPARTMENT_REGIONS` is the one place to change.
- **Expired alerts are archived, not deleted.** The old sweeper destroyed the audit trail. I added a
  nullable `expired_at` rather than a `status` column to keep the change minimal; listing filters on
  `expired_at IS NULL`.
- **`area` validation is strict.** `"central delhi"` is rejected even though a human would understand
  it — a silent black hole is worse than a 422.
- **Ticket contract divergence (not changed).** The Phase 2 ticket froze `POST /incidents/{id}/tasks`
  and `TaskCreateIn.assignee_id`; the shipped API is `POST /tasks/by-incident/{id}` and
  `assignee_ids: list[str]`. Lubna's frontend is built against the shipped shape. I did **not** rename
  anything — that would break her build. This is a ticket/implementation mismatch that needs the
  lead's decision, not an agent's.
- **`AlertOut` keeps the existing field names** (`title`/`body`/`area`), not the ticket's
  `headline`/`description`/`region`. Same reason: the frontend is built against the shipped shape.
- **Worklog date.** `docs/daily/README.md` says worklogs are "dated by that session's real calendar
  date"; this session began 2026-11-09 and ran past midnight into 2026-11-10, so the file is
  `2026-11-10`. No task file was edited (they are read-only for agents).

## Problems hit + fixes

1. **Sub-agents died twice.** Free-usage limit, then `getaddrinfo ENOTFOUND integrate.api.nvidia.com`
   (the harness's model provider — DNS resolved fine a minute later; it was transient). Only the docs
   sub-agent produced output, but it left **partial edits** in the tree. Fix: re-launched with
   "inspect the existing diff first, finish it, do not discard it" instructions, and did the backend
   P1 work directly rather than trusting the report of a killed agent.
2. **Alerts nobody could see.** `user.department` ("Fire & Rescue") was compared against `Alert.area`
   ("Central Delhi") — different namespaces, never matched. Department heads got broadcasts only.
   Fixed with the three-source union (AD-39) + 17 tests.
3. **`verify-module1.ps1` failed with 409 — and it was not a bug.** Two causes: (a) the backend groups a
   report under an existing incident when it shares ≥50% of its tokens with a same-region,
   same-category incident younger than 30 minutes, so run 2's probe landed on run 1's incident, which
   was still at phase `ACTIVE`; (b) production runs the **LLM** assessment backend, and it correctly
   assessed a title of random hex (`"Dispatch probe 7769f2…"`) as `DEFINITELY_FALSE` — it reads as a
   prank with no hazard in it. Fix: the probe rotates 14 (region, category) pairs and files a realistic
   hazard report. Both traps are documented in the script header.
4. **Gnani TTS returned 502 / direct 429.** Root cause: the provider is aggressively rate-limited and
   the first direct probe used a reduced request body; the exact production body returned
   **HTTP 200 in 1.93 s**. Transient upstream, not our proxy. Fix: retry the real body; the round-trip
   then succeeded through our own API twice.
5. **Playwright failed on stale copy.** `map.spec.ts` asserted "Live traffic and team GPS are not
   available" — the text I changed when wiring TomTom. Fix: updated the assertion to the current copy
   *and* added a check that the traffic layer is actually offered, so the test is stronger than before.
6. **The alert-preference form had the wrong dropdowns.** The "region" select was populated with incident
   **categories** and the "category" select with **severities**. Fix: added `NCR_REGIONS` to the web
   constants and wired both selects correctly.
7. **Windows-only tooling pain.** `grep`/`sed`/`head` do not exist in this PowerShell; `(app)` and
   `[id]` paths need `-LiteralPath`; PowerShell 5.1 mangles JSON passed as a native argument, so bodies
   go through a file (the pattern `verify-auth.ps1` already used — I copied it into the new script).
