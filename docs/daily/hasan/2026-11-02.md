## What shipped

Phase 2 backend (Module 1 dispatch arc) — all six slices:

1. **Tasks** (PL-7): `POST/GET /incidents/{id}/tasks`, `GET/PATCH /tasks/{id}`,
   `POST/GET /tasks/{id}/updates`. Transitions `OPEN->IN_PROGRESS->DONE` plus
   `OPEN->DONE` direct; backwards -> 409. Append-only `task_updates`. Assignee
   arrays (`assignee_ids`/`assignee_names`) resolved from the `assignments` table.
   Object scoping by department; RESPONSE_TEAM may only touch assigned tasks.
2. **Close + phase** (PL-8, PL-9): `POST /incidents/{id}/close` refuses with 409
   listing open task ids while any task is OPEN/IN_PROGRESS; `POST .../phase`
   strict `NONE->COORDINATING->ACTIVE->RESOLVED`; reopen endpoint.
   `set_response_phase()` added to incident_state (I7).
3. **Alerts**: `GET/POST /alerts`, prefs CRUD, `WS /ws/alerts` (Redis channel).
   CAP-shaped, adapted to existing model (title/body/area/expires_at).
4. **Stats** (PL-10, PL-11): `GET /stats/overview` role-scoped; poll
   participation = distinct voters / eligible-incident count.
5. **Audit**: `GET /audit/logs` (admin, filters).
6. **Voice** (T3): `POST /voice/stt` (multipart, 504 retry), `POST /voice/tts`
   (JSON -> WAV), `GET /voice/languages`. Config: `gnani_api_key`,
   `gnani_base_url`. Proxies keep the key server-side; Evon stays T4 (PL-17).
