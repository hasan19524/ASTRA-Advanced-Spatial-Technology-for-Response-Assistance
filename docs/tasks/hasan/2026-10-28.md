## 📜 The contract (Lubna builds against exactly this)

**REST** — all under `/api/v1`, Bearer token:

| Endpoint | Shape |
|---|---|
| `POST /incidents` | multipart/form-data: `title*`, `description*`, `category*` (the 8 enums), `region`, `latitude`, `longitude`, `location_text`, `photo` (file, optional — jpeg/png/webp ≤ 5MB) → **201** `{...IncidentOut, grouped: bool}` · 401 no token · 422 invalid |
| `GET /incidents` | query `category, assessment, verification, region, limit, offset` → `{items: IncidentOut[], total, limit, offset}` |
| `GET /incidents/{id}` | → `IncidentOut` + `reports[]` + `assessments[]` |

**Visibility rule (✅ decided):** every list/detail requires a token. Rows with
`sensitivity=RESTRICTED` **or** `visibility=HIDDEN` appear only for callers holding
`incident.view_restricted` (= CENTRAL_ADMIN + VERIFICATION_OFFICER). Everyone else: absent from
lists, **404** on direct id — never 403.

**IncidentOut:** `id, title, description, category, region, latitude, longitude, location_text,
sensitivity, assessment_status, visibility, verification, response_phase, lifecycle,
report_count, created_at, updated_at` (+ `grouped` on the POST response).
Detail adds `reports[]` (`content, source, media_path, created_at` — **no reporter identity**)
and `assessments[]` (`backend, outcome, confidence, reason, created_at`).

**WebSocket** — `ws://localhost:8000/ws/map?token=<access_token>` (AD-10: token verified *before*
accept → missing/invalid closes **4401**):
- on connect → `{"channel":"incidents:map","type":"connected"}`
- new public incident → `{"channel":"incidents:map","type":"incident.created","data":<IncidentOut>}`
- publish condition: `visibility=PUBLIC_UNVERIFIED AND sensitivity=PUBLIC` (the public map query)
- fanout via **Redis pub/sub topic `incidents:map`** (✅ decided)
